# 千恋＊万花 · 小米手环移植版

《千恋＊万花》（SAGA PLANETS 全年龄恋爱 ADV）在小米手环 / Redmi Watch 上的运行版本：完整剧本 112 个场景、六条可攻略线路、二周目后日谈，全部装进手环屏幕。

本项目是两个上游仓库的组合移植：

| 部分 | 来源 | 说明 |
|------|------|------|
| 剧情内容（剧本 + 立绘 + 背景 + 事件图） | [qlwh-mibandported](https://github.com/hezdaaa/qlwh-mibandported) | 千恋＊万花内容包，55901 页剧本 + 809 张图片资源 |
| 游戏引擎 + 手环 UI | [Sanoba-Witch-MiBand-10](https://github.com/hrk666666/Sanoba-Witch-MiBand-10) | 平台无关的 VnEngine（data-driven）+ 手环快应用界面 |

即：**内容采用 qlwh 仓库，引擎与 UI 采用 Sanoba 仓库**，二者在本工程内合并为一个可构建 RPK 的新工程。

## 功能特性

- **完整剧情**：112 个场景 / 55901 页剧本 / 74504 个剧本节点，覆盖共通线 + 六条个人线（芳乃 / 茉子 / 丛雨 / 蕾娜 / 小春 / 芦花），每线独立进入、独立结局，不串线。
- **二周目机制**：每条主线通关后自动记录（存储持久化）；隐藏线（小春 / 芦花）入口首周目置灰、通关任意一条主线后解锁；主菜单"后日谈"入口，通关对应线后播放结局后延续剧情（芳乃线婚后日常、蕾娜线蜜月等）。
- **资源完整**：背景 92 张、立绘 141 张（统一压至 480 高，全屏显示不截断）、事件图 570 张。
- **体验修复**：进入游戏不再强制拉高系统亮度；确认弹窗长文本正常换行；读档不再偶发"只有立绘没有背景"；CG 显示时立绘不残留。
- **设备适配**：三个分支分别对应胶囊屏（手环 10）、方屏（10 Pro / 9 Pro / 8 Pro）、自适应包（见下）。

## 分支与包名

| 分支 | 包名 | 目标设备 | 说明 |
|------|------|----------|------|
| `main` | `com.hrk.qlwh.band` | 小米手环 10（212×520 胶囊屏） | 主版本 |
| `pro` | `com.hrk.qlwh.bandp` | 手环 10 Pro / 9 Pro / 8 Pro（336×480 方屏） | 方屏适配版 |
| `auto` | `com.hrk.qlwh.bandauto` | 胶囊屏 + 方屏 | 自适应测试版，一个包经媒体查询适配两类屏幕 |

## 快速开始

```bash
npm ci                      # 安装依赖（网络受限时：npm ci --registry=https://registry.npmmirror.com/）
npm start                   # 模拟器 / 真机调试（aiot start --watch）
npm run release             # 构建签名 RPK（JSC 字节码，产物在 dist/）
npm test                    # 单测 + 端到端路线回归
npm run validate            # 内容包完整性校验（剧本 / 跳转目标 / 资源存在性）
```

本地构建要求项目根目录存在 `sign/`（`private.pem` + `certificate.pem`，已提交进 git，保证各版本签名一致、可覆盖安装）。

## 剧本格式（引擎契约）

引擎是 data-driven 的：任何内容包只要符合 `docs/剧本格式规范v1.1.md`（`game.txt` + `scn/*.txt` + 资源目录），即可被引擎运行，**不需要改动引擎代码**。

节点类型速览（完整见规范文档）：

| 类型 | 含义 | 示例 |
|------|------|------|
| 0 | 标签 / 跳转点 | `[0, "label"]` |
| 1 | 章节标题 | `[1, "第一章"]` |
| 2 | 背景 | `[2, "bg_空_青空"]` |
| 3 | 对话 | `[3, "说话人", "文本", [["立绘", "center", "change"]]]` |
| 4 | 选项 | `[4, [["文字","目标","表达式","条件?"], …]]` |
| 5 | 事件 CG | `[5, "evXXX"]` |
| 6 | 跳转 | `[6, "target_label"]` |
| 7 | 立绘操作 | `[7, "角色_表情", "center", "fadein"\|"fadeout"\|"change"]` |
| 8 | 音乐 | `[8, "曲名", "bgm", "loop"]` |
| 9 | 特效 | `[9, "whiteflash", 时长ms]` |
| 10 | 变量 | `[10, "f.x = 1, f.y++"]` |

## 转换规则（tools/convert_qlwh.py）

对上游 `scriptData1..112.txt`（每页 JSON：b/s/t/c/co/c1..c5/c1t..c5t/cg）逐页转换：

- 顺序页 → 对话节点 `[3,说话人,文本,立绘]`；背景变化 → `[2,背景]`
- 立绘 `c` → 对话第 4 字段 `[["键","center","change"]]`；消失 → `[7,"*","center","fadeout"]`
- 事件图 `cg` → `[5,资源]`（`ev*`→.jpg，其余→.png；缺资源跳过并记 missing）
- 选项页 → `[4,[[文本,目标,表达式]…]]`，目标取上游 `cNt`（含跨块 `块号@*p页`），表达式 `f.c<页>=<序号>`
- 合流（noNextPages）→ `[6,目标]`；隐藏路由（hiddenPages）→ 多条条件 `[6,目标,条件]` + 兜底；结局 → `[6,"*gameend_<名>"]`
- 章节标记 → `[1,"CHAPTERx-y"]`

**二周目扩展**：结局节点后引擎写入通关标记（`storage` 键 `qlwh_clears`）；隐藏线选项加条件表达式（首周目 `enabled=false` 置灰 + 引擎 `choose` 守卫）；后日谈章节表（`AFTER_STORIES`，各线结局后起始行）注册在 `src/common/constants.js`。

## 已知行为（与上游一致性）

- **上游死路由（1.2.0 已修复）**：上游 `noNextPages` 曾把钓鱼支线结尾（页 5925）错误配置为直接跳合流点，跳过选项页 5926，导致判定芳乃线、蕾娜线的标记从未被设置；本工程已移除该错误跳转，六条线路各自独立可达。蕾娜线入口也已从错误指向（共通线中段）修正为蕾娜线第 4 章开头。

# 移植其他游戏：操作指南

本节面向"想把另一款文字冒险游戏（Galgame / ADV / 视觉小说）搬上手环"的开发者。流程分六个阶段，按顺序走即可。

## 阶段 0：版权与授权（先做，别跳过）

- 确认你有权处理该游戏的内容：自己购买的正版素材、官方授权、或明确允许再分发的开源/免费作品。**未经授权搬运商业游戏内容并公开分发是侵权**，本项目是技术演示用途，不构成范例。
- 决定发布形态：只做本地自用（无需授权，但别公开仓库）、私有仓库、还是公开开源。公开仓库必须在 README 写明内容版权归属 + 非从属关系声明（见文末模板）。

## 阶段 1：拿到并识别上游数据

你需要三样东西：**剧本脚本**、**图片资源**（立绘 / 背景 / CG）、**分支结构**（选项 → 目标的跳转关系）。

- **本项目来源（qlwh 格式）**：`scriptData1..112.txt`，每页一个 JSON 对象，字段含义：`s`=场景页、`t`=文本、`c`=说话人、`b`=背景、`c1..c5`=立绘、`c1t..c5t`=选项目标、`cg`=事件图、`noNextPages`=无后续直接跳转、`hiddenPages`=隐藏路由。直接改 `tools/convert_qlwh.py` 的字段映射即可。
- **其他常见格式**：Ren'Py 的 `rpy` 脚本（解析后是带标签的文本流）、吉里吉里 `KAG`（`*.ks` 标签化文本）、`scenario` 类 JSON。**原则：先把上游格式"压平"成 顺序页 + 跳转 两种信息，再映射到 vn-1.1 节点**。选项的目标经常是"页号/标签"而非顺序，转换器里维护一张 `标签/页号 → 节点索引` 的映射表，所有跳转统一查表，避免手写硬编码。
- **分支结构缺失时**（上游只有顺序文本没有跳转表）：按选项文本人工推断分支点，用 `[4]` 选项节点重建，每个选项目标指向后续章节开头的 `[0,"label"]` 标签。目标不确定的分支宁可先合并（`[6]` 指向同一合流点），保证能跑通，再逐步细化。

## 阶段 2：转换器适配（tools/convert_qlwh.py）

转换器输出 `scn/chunkNNN.txt` + 更新 `game.txt`。适配要点：

1. **节点映射**：对话→`[3]`、背景→`[2]`、立绘→`[7]`/对话第 4 字段、选项→`[4]`、跳转→`[6]`、结局→`[6,"*gameend_<线名>"]`、章节→`[1]`。**立绘动作语义**：上游"换立绘"→`change`、"立绘消失"→`fadeout`，映射错了画面会叠一堆立绘。
2. **跨块跳转**：上游选项目标常写成 `块号@页号`，转换器必须翻译成"目标块内对应标签的跳转"（`[6,"chunkN@label"]`），引擎已支持跨场景目标。
3. **结局识别**：结局页通常有特征（特定命令 / 特定标记），转换器里单独登记一份"结局表"（`*gameend_<名>`），这既是回归测试的验收点，也是二周目机制（通关记录 / 后日谈入口）的数据源。
4. **输出后用 `npm run validate`**：校验剧本合法性、跳转目标存在性、资源存在性，一次性列出所有 missing。

## 阶段 3：资源处理（手环内存是硬约束）

手环快应用的内存远小于手机，图片是最主要的体积来源。**所有图片必须压缩到合理尺寸，不是原图直出**：

| 资源 | 本项目规范 | 原因 |
|------|------------|------|
| 立绘 | 统一 480 高（等比缩放） | 太高会被屏幕截断只剩腿部；太低糊 |
| 背景 | 适配目标屏幕分辨率（胶囊屏 212×520 / 方屏 336×480） | 原图通常是 1280×720+，直接放内存会爆 |
| 事件图 CG | 同上，等比压缩 | CG 张数多（570 张），单张要小 |
| 格式 | PNG/JPG，避免 GIF | Vela 的 image 组件只保证 png/jpg |

压缩工具：ImageMagick 批量 `convert -resize` 即可。**改过资源尺寸后必须重新算 UI 布局**：字号、容器高度、边距都要跟着屏幕尺寸调，别只换图。

## 阶段 4：引擎配置（不改引擎代码）

1. `src/common/game.txt`：改 `id`（建议英文短 id，用作存储前缀）、`title`、`scenarios.main` 块数。
2. 剧本放 `src/common/scn/*.txt`（**必须 .txt 扩展名存 JSON**，实体机读 `.json` 扩展名有兼容问题）。
3. 资源目录：`bg/`（背景）、`ch/`（立绘）、`ev/`（事件图）、`sd/`（SD 装饰）——转换器与引擎按此约定找文件。
4. 新增功能（二周目 / 隐藏线 / 后日谈）照抄本项目模式：`constants.js` 加通关标记键 + 章节表，`scriptRuntime.js` 加 `*gameend_` 处理与选项守卫，首页加入口。

## 阶段 5：UI 与设备适配

- **屏幕尺寸**：胶囊屏 212×520（手环 10）、方屏 336×480（10 Pro / 9 Pro / 8 Pro）。manifest 的 `designWidth` 决定 px 缩放基准（本项目 212）。
- **单位**：样式一律 `dp` 或 px（按 designWidth 缩放），**别用手机项目的 px 直抄**。
- **媒体查询**：方屏 / 胶囊屏差异用 `@media (shape: circle/rect/pill-shaped)` 区分；想一个包适配多设备，参考 `auto` 分支的做法（图片 `object-fit: cover` + 媒体查询）。
- **字号**：手环正文 13-14dp、按钮 11-12dp、标题 15-16dp，比手机小 2-3 级。
- **长文本**：正文区用 `<scroll scroll-y="true">` 包裹，别给内容区写死高度；确认弹窗的标题/正文加宽度约束，否则长文本与按钮挤一行。

## 阶段 6：构建、验证、发布

```bash
npm run validate   # 内容包校验（每次转换后必跑）
npm test           # 单测 + 路线回归（2 条主路线 + 6 条路线扫描）
npm run release    # 构建签名 RPK（JSC 字节码，dist/）
npm start          # 模拟器调试（aiot start --watch）
```

- **签名**：`sign/` 目录（private.pem + certificate.pem）创建后**提交进 git**，后续版本签名一致才能覆盖安装。
- **回归测试**：至少覆盖"每条线路从入口到结局"的端到端用例（本项目 `tests/regression-qlwh.mjs` 扫描 6 条路线），跳转错一个目标整条线就串了。
- **发布**：release 包通过小米运动健康 App 的 Debug → 第三方应用菜单安装到真机；模拟器（Vela AVD）可先验证渲染与基本交互。

## 移植常见坑（按踩坑频率排序）

| 坑 | 现象 | 对策 |
|----|------|------|
| **模块顶层加载不存在的系统模块** | 手环 9/9 Pro 点开始游戏直接重启 | 适配器（platformAdapter/aiotAdapter）不得顶层 `import` 设备缺失的模块（如 `@app-module/system.audio`），按需 try-catch |
| **快进 / 跳到下一选项导致线路串线** | 芳乃线结束又自动播茉子线 | 快进逻辑遇 `*gameend_` 节点必须立即结束，遇普通跳转正常执行；加"快进走某线正确结束"的回归用例 |
| **for 循环列表不渲染** | 弹窗里列表空白，页面根部 for 正常 | Vela 模板不支持单参数 `for="{{item in list}}"`，必须双参数 `(index, item)`；`if` 嵌套多层 div 内的 for 也可能不渲染，列表结构尽量压平 |
| **storage 当成同步用** | 读档偶发状态错乱 | `@system.storage.get` 是回调式，onInit 里读完再渲染，别在 onReady 前访问元素 |
| **图片资源过大** | 应用闪退 / 白屏 | 全部压缩到屏幕尺寸级，列表用 `<list>` 虚拟滚动，别用 `<div>+for` 渲染长列表 |
| **emoji 进界面** | 显示为方块/乱码 | Vela 对 emoji 支持差，用 SVG / 字体图标 / 文字替代 |
| **px 单位直抄** | 元素溢出屏幕可左右滚动 | 根容器固定宽度（212dp），样式用 dp，字号按手环规范 |
| **模拟器窗口点击无效** | 实机验证点不了菜单 | 模拟器重启后输入通道可能断（环境问题）：重启模拟器、确认窗口在顶层未被浏览器遮挡、必要时重启虚拟显示 |
