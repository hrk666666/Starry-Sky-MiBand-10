# 星空列车与白的旅行 · 小米手环移植版

《星空列车与白的旅行》（しらたまこ 全年龄 ADV）在小米手环（胶囊屏）上的运行版本：完整 17 章剧本、角色立绘、背景与事件 CG、存档读档，全部装进手环屏幕。

本项目是两个上游仓库的组合移植：

| 部分 | 来源 | 说明 |
|------|------|------|
| 剧情内容（剧本 + 立绘 + 背景 + 事件图） | [starry-rw5](https://github.com/xuanyide01/starry-rw5) | 《星空列车与白的旅行》Vela 移植内容包（17 章剧本 + 527 张图片资源） |
| 游戏引擎 + 手环 UI | [Sanoba-Witch-MiBand-10](https://github.com/hrk666666/Sanoba-Witch-MiBand-10) | 平台无关的 VnEngine（data-driven）+ 手环快应用界面 |

即：**内容采用 starry-rw5 仓库，引擎与 UI 采用 Sanoba 仓库**，二者在本工程内合并为一个可构建 RPK 的新工程。

## 功能特性

- **完整剧情**：17 个场景 / 13765 条对白 / 31746 个剧本节点，完整收录《星空列车与白的旅行》本篇全部章节。
- **剧情分支**：4 组选项（直接给她 / 晃晃再给她；吃东西 / 和野鸟小姐喝点酒 / 和鹰世聊会儿天；留在这里 / 向花江小姐打个招呼吧 / 独处一会儿；鹰世读的是…… / 野鸟小姐读的是……），分支后合流至同一结局。
- **资源完整**：背景 56 张、立绘 368 张（含大小差分）、事件图 103 张。
- **存档系统**：自动存档 + 手动存档（30 槽），支持从上次开始、读取存档。
- **阅读体验**：打字机效果、快进、自动播放、跳到下一选项、文字加粗/字号/速度可调。
- **圆形应用图标**：沿用原版无标题文字的圆形透明 PNG。

## 剧本格式（引擎契约）

引擎是 data-driven 的：任何内容包只要符合 `docs/剧本格式规范v1.1.md`（`game.txt` + `scn/*.txt` + 资源目录），即可被引擎运行，**不需要改动引擎代码**。

节点类型速览（完整见规范文档）：

| 类型 | 含义 | 示例 |
|------|------|------|
| 0 | 标签 / 跳转点 | `[0, "label"]` |
| 1 | 章节标题 | `[1, "第一章"]` |
| 2 | 背景 | `[2, "bg_white"]` |
| 3 | 对话 | `[3, "说话人", "文本", [["立绘", "center", "change"]]]` |
| 4 | 选项 | `[4, [["文字","目标","表达式","条件?"], …]]` |
| 5 | 事件 CG | `[5, "evcg01a"]` |
| 6 | 跳转 | `[6, "target_label"]` |
| 7 | 立绘操作 | `[7, "角色_表情", "center", "fadein"\|"fadeout"\|"change"]` |
| 8 | 音乐 | `[8, "曲名", "bgm", "loop"]` |
| 9 | 特效 | `[9, "whiteflash", 时长ms]` |
| 10 | 变量 | `[10, "f.x = 1, f.y++"]` |

## 转换规则（tools/convert_starry.py）

对上游 `story/1.txt..17.txt`（JSON 节点数组，op 格式）逐章转换：

- `background`（非 event）→ 背景节点 `[2,图名]`；`restoreBackground` → 恢复最近非 event 背景（转换期静态模拟）
- `background`（event=true）→ 事件 CG 节点 `[5,图名]`（evcg / aban 系列，全屏）
- `body`（有图）→ 立绘节点 `[7,图名,"center","change"]`；`body`（空）→ `[7,"","center","fadeout"]` 清空
- `text` → 对话节点 `[3,说话人,文本]`
- `choice` → 选项节点 `[4,[[文本,目标]…]]`，目标行插入 `[0,"label"]` 标签
- `jump` → `[6,"label"]`（同章）/ `[6,"0XX@label"]`（跨章，`XX`=目标章号）
- `end` → `[6,"gameend_starry"]`（引擎统一结束处理）

**跨章跳转**：上游目标是 `[章号, 行号]`，转换器在目标行插入标签并把跳转写成 `scnId@label`（如 `007@s11_1444`），引擎已支持跨场景目标。

## 已知行为

- **单线结构**：本作 4 组选项均为分支后合流，最终一个结局；无多线路 / 二周目，`AFTER_STORIES` 为空、主菜单无后日谈入口。
- **无声版**：上游 rw5 版即不含音频，本包不携带音乐/音效资源。
- **资源格式**：全部图片为 PNG（含透明立绘），引擎 `RES_TYPES` 与 UI 层均已按 `.png` 适配。

# 移植其他游戏：操作指南

本节面向"想把另一款文字冒险游戏（Galgame / ADV / 视觉小说）搬上手环"的开发者。流程分六个阶段，按顺序走即可。

## 阶段 0：版权与授权（先做，别跳过）

- 确认你有权处理该游戏的内容：自己购买的正版素材、官方授权、或明确允许再分发的开源/免费作品。**未经授权搬运商业游戏内容并公开分发是侵权**，本项目是技术演示用途，不构成范例。
- 决定发布形态：只做本地自用（无需授权，但别公开仓库）、私有仓库、还是公开开源。公开仓库必须在 README 写明内容版权归属 + 非从属关系声明（见文末模板）。

## 阶段 1：拿到并识别上游数据

你需要三样东西：**剧本脚本**、**图片资源**（立绘 / 背景 / CG）、**分支结构**（选项 → 目标的跳转关系）。

- **本项目来源（starry 格式）**：`story/1..17.txt`，每个文件一个 JSON 数组，节点字段 `op`：`background`（含 `event` 标记）、`body`（立绘，空串=清除）、`text`（含 speaker）、`choice`（`items[].to` = [章,行]）、`jump`（`to` = [章,行]）、`restoreBackground`、`end`。直接改 `tools/convert_starry.py` 的节点映射即可。
- **其他常见格式**：Ren'Py 的 `rpy` 脚本（解析后是带标签的文本流）、吉里吉里 `KAG`（`*.ks` 标签化文本）、`scenario` 类 JSON。**原则：先把上游格式"压平"成 顺序页 + 跳转 两种信息，再映射到 vn-1.1 节点**。选项的目标经常是"页号/标签"而非顺序，转换器里维护一张 `标签/页号 → 节点索引` 的映射表，所有跳转统一查表，避免手写硬编码。
- **分支结构缺失时**（上游只有顺序文本没有跳转表）：按选项文本人工推断分支点，用 `[4]` 选项节点重建，每个选项目标指向后续章节开头的 `[0,"label"]` 标签。目标不确定的分支宁可先合并（`[6]` 指向同一合流点），保证能跑通，再逐步细化。

## 阶段 2：转换器适配（tools/convert_starry.py）

转换器输出 `scn/chunkNNN.txt` + 更新 `game.txt`。适配要点：

1. **节点映射**：对话→`[3]`、背景→`[2]`、立绘→`[7]`、选项→`[4]`、跳转→`[6]`、结局→`[6,"gameend_<名>"]`。**立绘动作语义**：上游"换立绘"→`change`、"立绘消失"→`fadeout`，映射错了画面会叠一堆立绘。
2. **跨块跳转**：上游选项目标常写成 `[章,行]` 或 `块号@页号`，转换器必须翻译成"目标块内对应标签的跳转"（`[6,"scnId@label"]`），引擎已支持跨场景目标。转换器先预扫描全部跳转目标、在目标行插入标签，再生成跳转节点。
3. **结局识别**：结局节点（`end` / 特定命令）→ 统一 `[6,"gameend_<名>"]`；单线作品不登记线路表即可，引擎对未知 gameend 目标只结束不记通关标记。
4. **输出后用 `npm run validate`**：校验剧本合法性、跳转目标存在性（同章 / 跨章 label 都要查）、资源存在性，一次性列出所有 missing。

## 阶段 3：资源处理（手环内存是硬约束）

手环快应用的内存远小于手机，图片是最主要的体积来源。**所有图片必须压缩到合理尺寸，不是原图直出**：

| 资源 | 本项目规范 | 原因 |
|------|------------|------|
| 立绘 | 透明底 PNG，高度 286（上游原尺寸，不放大） | 太高会被屏幕截断只剩腿部；太低糊 |
| 背景 | 16:9 横图（432×243，上游原尺寸） | 胶囊屏 contain 显示为画面横条 + 上下黑边 |
| 事件图 CG | 同上，等比压缩 | CG 张数多（103 张），单张要小 |
| 格式 | PNG/JPG，避免 GIF | Vela 的 image 组件只保证 png/jpg |

压缩工具：ImageMagick 批量 `convert -resize` 即可。**改过资源尺寸后必须重新算 UI 布局**：字号、容器高度、边距都要跟着屏幕尺寸调，别只换图。

## 阶段 4：引擎配置（不改引擎代码）

1. `src/common/game.txt`：改 `id`（建议英文短 id，用作存储前缀）、`title`、`scenarios.main` 块数。
2. 剧本放 `src/common/scn/*.txt`（**必须 .txt 扩展名存 JSON**，实体机读 `.json` 扩展名有兼容问题）。
3. 资源目录：`bg/`（背景）、`ch/`（立绘）、`ev/`（事件图）——转换器与引擎按此约定找文件。**扩展名统一 `.png`**（改资源后同步改 `engine/resourceManager.js` 的 `RES_TYPES` 与 `game.ux` 的图片 src 拼接）。
4. 新增功能（二周目 / 隐藏线 / 后日谈）照抄千恋版模式：`constants.js` 加通关标记键 + 章节表，`scriptRuntime.js` 加 `gameend_` 处理与选项守卫，首页加入口。

## 阶段 5：UI 与设备适配

- **屏幕尺寸**：胶囊屏 212×520（手环 9/10/11）。manifest 的 `designWidth` 决定 px 缩放基准（本项目 212）。
- **单位**：样式一律 `dp` 或 px（按 designWidth 缩放），**别用手机项目的 px 直抄**。
- **媒体查询**：方屏 / 胶囊屏差异用 `@media (shape: circle/rect/pill-shaped)` 区分。
- **字号**：手环正文 13-14dp、按钮 11-12dp、标题 15-16dp，比手机小 2-3 级。
- **长文本**：正文区用 `<scroll scroll-y="true">` 包裹，别给内容区写死高度；确认弹窗的标题/正文加宽度约束，否则长文本与按钮挤一行。
- **图片后缀**：Vela 的 image 组件不自动探测扩展名，UI 层拼 src 时后缀必须与资源实际格式一致（`.png` 资源配 `.png`，写错 `.jpg` 直接加载失败黑屏）。

## 阶段 6：构建、验证、发布

```bash
npm run validate   # 内容包校验（每次转换后必跑）
npm test           # 单测 + 路线回归（全选第 1 项 / 全选最后一项 / 快进 三条路线）
npm run release    # 构建签名 RPK（JSC 字节码，dist/）
npm start          # 模拟器调试（aiot start --watch）
```

- **签名**：`sign/` 目录（private.pem + certificate.pem）创建后**提交进 git**，后续版本签名一致才能覆盖安装。
- **回归测试**：至少覆盖"从入口到结局"的端到端用例（本项目 `tests/regression-starry.mjs` 走 3 条路线），跳转错一个目标整条流程就断了。
- **发布**：release 包通过小米运动健康 App 的 Debug → 第三方应用菜单安装到真机；模拟器（Vela AVD）可先验证渲染与基本交互。

## 移植常见坑（按踩坑频率排序）

| 坑 | 现象 | 对策 |
|----|------|------|
| **模块顶层加载不存在的系统模块** | 手环 9/9 Pro 点开始游戏直接重启 | 适配器（platformAdapter/aiotAdapter）不得顶层 `import` 设备缺失的模块（如 `@app-module/system.audio`、`system.brightness`），按需 try-catch |
| **图片后缀写错** | 背景 / 立绘 / CG 黑屏或空白 | UI 层拼 src 的后缀必须与实际资源格式一致；`RES_TYPES` 与各页面模板逐一核对 |
| **快进 / 跳到下一选项导致线路串线** | 上一条线结束又自动播下一条 | 快进逻辑遇 `gameend_` 节点必须立即结束，遇普通跳转正常执行；加"快进走完整流程正确结束"的回归用例 |
| **for 循环列表不渲染** | 弹窗里列表空白，页面根部 for 正常 | Vela 模板不支持单参数 `for="{{item in list}}"`，必须双参数 `(index, item)`；`if` 嵌套多层 div 内的 for 也可能不渲染，列表结构尽量压平 |
| **storage 当成同步用** | 读档偶发状态错乱 | `@system.storage.get` 是回调式，onInit 里读完再渲染，别在 onReady 前访问元素 |
| **图片资源过大** | 应用闪退 / 白屏 | 全部压缩到屏幕尺寸级，列表用 `<list>` 虚拟滚动，别用 `<div>+for` 渲染长列表 |
| **emoji 进界面** | 显示为方块/乱码 | Vela 对 emoji 支持差，用 SVG / 字体图标 / 文字替代 |
| **px 单位直抄** | 元素溢出屏幕可左右滚动 | 根容器固定宽度（212dp），样式用 dp，字号按手环规范 |
